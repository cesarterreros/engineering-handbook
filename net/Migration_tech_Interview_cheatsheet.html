Technical Interview Cheat Sheet

1. EF Core (Entity Framework)

Migrations — What & Why

A migration is a versioned C# file (in /Migrations) describing incremental schema changes so the DB model stays in sync with your entity model. Each has Up() (apply) / Down() (revert), plus a snapshot file (ModelSnapshot.cs) EF diffs against to compute the next migration. Never hand-edit the snapshot.

Core CLI (dotnet-ef)

# install/update the tool
dotnet tool install --global dotnet-ef
dotnet add package Microsoft.EntityFrameworkCore.Design

# create / remove (last, if not applied)
dotnet ef migrations add InitialCreate
dotnet ef migrations remove

# apply to DB (update = "migrate to latest or named")
dotnet ef database update
dotnet ef database update AddOrders   # target a migration
dotnet ef database update 0           # revert ALL (rollback)

# inspect
dotnet ef migrations list
dotnet ef migrations has-pending-model-changes

Multi-project: use -p (project holding migrations) & -s (startup project), e.g. dotnet ef migrations add X -p Data -s Api. PMC equivalents: Add-Migration, Update-Database, Remove-Migration.

Applying in Production

  • SQL script (preferred/safest): generate, review, run via DBA/CI.
    dotnet ef migrations script FromMig ToMig -o migrate.sql. Use --idempotent so it checks __EFMigrationsHistory and only applies missing ones.
  • Bundle: self-contained executable, great for CI/CD (no SDK/tool on server).
    dotnet ef migrations bundle → ./efbundle.
  • Avoid context.Database.Migrate() at app startup in multi-instance/prod: causes race conditions, needs elevated DB rights, and blocks rollout on failure. Fine for local/dev or single-instance.
// dev-only auto-migrate
using var scope = app.Services.CreateScope();
var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
await db.Database.MigrateAsync();

Gotchas & Best Practices

  • __EFMigrationsHistory: tracking table EF uses to know which migrations already ran (idempotency).
  • Data loss warning: dropping columns/tables emits a warning in generated code — review Up() before applying.
  • Custom SQL / seed: add migrationBuilder.Sql("...") for data moves; use HasData() for model seed data (tracked by migrations).
  • Renames: EF often sees a rename as drop+add (data loss). Hand-edit to RenameColumn/RenameTable.
  • Team workflow: one migration per PR; if two devs add migrations concurrently, re-generate after merge so the snapshot is linear.
  • Reset (dev only): delete /Migrations + drop DB, then re-add InitialCreate.
  • EF 9/10: --idempotent scripts, bundles, and has-pending-model-changes are the modern, CI-friendly path; static-analysis catches model/snapshot drift.

Query Filters

Applied globally to entities. Essential for soft-deletes and multi-tenancy.

protected override void OnModelCreating(ModelBuilder mb) {
    mb.Entity<TenantData>().HasQueryFilter(t => t.TenantId == _currentTenantId);
}

Bypass filter via .IgnoreQueryFilters().

Concurrency

Optimistic concurrency: EF Core holds no locks — conflicts are detected only at SaveChanges(). A concurrency token is added to the WHERE clause of UPDATE/DELETE; if 0 rows match, another user changed the row.

  • [Timestamp] / IsRowVersion(): DB auto-updates a byte[] on every change (best for SQL Server).
  • [ConcurrencyCheck] / IsConcurrencyToken(): Track an existing column (e.g., Version int, LastModified) — portable to any provider.
public class Product {
    public int Id { get; set; }
    [Timestamp] // Maps to rowversion in SQL
    public byte[] RowVersion { get; set; }
}

Handle the conflict: catch DbUpdateConcurrencyException on SaveChanges(), inspect ex.Entries, then pick a strategy.

try { await context.SaveChangesAsync(); }
catch (DbUpdateConcurrencyException ex) {
    foreach (var entry in ex.Entries) {
        var db = await entry.GetDatabaseValuesAsync();
        if (db == null) { /* row deleted by another user */ }
        else entry.OriginalValues.SetValues(db); // refresh token, then retry
    }
}

Resolution strategies: Store Wins (reload DB values), Client Wins (overwrite originals with DB, re-apply user changes), or Merge (property-by-property). Wrap SaveChanges() in retry logic.

2. PostgreSQL

Schema & Indexing

  • Schemas: Namespaces for tables (e.g., public, tenant_a). SET search_path TO tenant_a;
  • Indexing: B-Tree (default, > < =), GIN (for JSONB/Full-text), GiST (geometric/range).
CREATE INDEX idx_user_email ON users (email);
CREATE INDEX idx_jsonb_data ON docs USING GIN (payload);

Multi-Tenant & RLS (Row-Level Security)

Data isolation at the DB engine level using shared schema.

ALTER TABLE orders ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON orders
USING (tenant_id = current_setting('app.current_tenant')::uuid);

In the app middleware or EF interceptor, execute:
SET LOCAL app.current_tenant = 'tenant-uuid';

3. OAuth2/OIDC + JWT Middleware

Microsoft.Identity.Web

Simplifies Azure AD / Entra ID integration.

builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddMicrosoftIdentityWebApi(builder.Configuration, "AzureAd");

Tenant Middleware (JWT Extraction)

Extract tenant ID from validated JWT claims (e.g., tid claim) and inject into scoped services (like EF Core DbContext).

app.Use(async (context, next) => {
    var tidClaim = context.User.FindFirstValue(
        "http://schemas.microsoft.com/identity/claims/tenantid");
    
    if (tidClaim != null) {
        var tenantContext = context.RequestServices
                                   .GetRequiredService<ITenantContext>();
        tenantContext.TenantId = tidClaim;
    }
    await next();
});

4. Docker + Basic Kubernetes

Docker Multi-stage Build

FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY *.csproj .
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /app

FROM mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled
WORKDIR /app
COPY --from=build /app .
ENTRYPOINT ["dotnet", "Api.dll"]
  • Why: small final image, less attack surface, no SDK/source/build secrets shipped.
  • Layer caching: COPY *.csproj + dotnet restore before copying full source so restore is cached.
  • Slim base + non-root: use -chiseled/alpine/distroless and USER app; add .dockerignore (bin, obj, .git, .env).
  • Target a stage: docker build --target build . (e.g. run a test stage in CI).

Secrets Handling

  • Never bake secrets: avoid ENV/ARG secrets or COPY .env — visible via docker history/inspect; stay in layers even if deleted later.
  • Build-time: BuildKit RUN --mount=type=secret,id=token ... → docker build --secret id=token,src=./token.txt (not stored in any layer).
  • Runtime: inject at start — K8s Secrets mounted as files (/run/secrets/...) preferred over env vars; better yet use managed/workload identity so no static secret exists.

CI Image Gates

  • Scan & fail: Trivy/Grype/Docker Scout — trivy image --exit-code 1 --severity HIGH,CRITICAL.
  • Lint & secrets: hadolint (Dockerfile), gitleaks/trufflehog (committed secrets).
  • Sign & provenance: Cosign/Sigstore signatures + SBOM (Syft); verify at deploy.
  • Policy/admission: Kyverno/Gatekeeper/OPA enforce non-root, trusted registry, no :latest.
  • Immutable deploys: deploy by digest (image@sha256:...) so what you scanned is what you run.

Kubernetes Core Concepts

Architecture: Control plane = api-server (front door) + etcd (state) + scheduler (places Pods) + controller-manager (reconcile loops). Worker node = kubelet (runs Pods) + kube-proxy (Service routing) + container runtime (containerd via CRI; dockershim removed in 1.24). Model is declarative desired-state reconciliation.

  • Pod: Smallest deployable unit (1+ containers sharing network/storage). Rarely created directly.
  • ReplicaSet: Keeps N identical Pods running (managed by Deployment).
  • Deployment: Stateless apps; ReplicaSet mgmt, rolling updates & rollback (kubectl rollout undo).
  • StatefulSet: Stateful apps (DBs) — stable identity + ordered, persistent storage.
  • DaemonSet: One Pod per node (agents, logging). Job/CronJob: run-to-completion / scheduled.
  • Service: Stable IP/DNS + load-balancing via label selector. ClusterIP (internal), NodePort, LoadBalancer, ExternalName.
  • Ingress / Gateway API: HTTP(S) host/path routing into cluster (Gateway API is the modern successor).
  • ConfigMap / Secret: Externalized config / sensitive data (Secrets are only base64, not encrypted by default).
  • Namespace: Logical isolation + quotas. PV/PVC + StorageClass: storage abstraction & dynamic provisioning.
  • Labels & selectors: How objects link (Service→Pods, Deployment→Pods). Mismatch = classic bug.
  • requests vs limits: requests drive scheduling; over-limit → memory=OOMKilled, CPU=throttled.
  • Probes: readiness (take traffic?), liveness (restart if stuck), startup (slow boot).
  • Reliability: HPA (scale Pods), Cluster Autoscaler/Karpenter (nodes), PodDisruptionBudget, self-healing.
  • Security: RBAC + ServiceAccount (least privilege), securityContext (runAsNonRoot), NetworkPolicy, Pod Security Admission.
  • Extend: CRDs + Operators (custom API + reconcile logic). Config: Kustomize (overlays) vs Helm (templated charts).
  • Debug Pod states: Pending, ImagePullBackOff, CrashLoopBackOff, OOMKilled — use logs/describe/get events.

Manifest = YAML with 4 top-level keys: apiVersion, kind, metadata, spec. Apply with kubectl apply -f.

apiVersion: apps/v1
kind: Deployment
metadata: { name: my-api }
spec:
  replicas: 2
  selector:
    matchLabels: { app: api }
  template:
    metadata: { labels: { app: api } }
    spec:
      containers:
      - name: api
        image: myapi:v1
        ports: [{ containerPort: 8080 }]

Common kubectl Commands

kubectl apply -f app.yaml            # create/update declaratively
kubectl get pods -o wide -A            # list Pods (all namespaces, node info)
kubectl describe pod <name>           # details + events (first stop for debugging)
kubectl logs <pod> -f [-c <ctr>] [-p]  # follow logs; -p = previous crash
kubectl exec -it <pod> -- sh           # shell into a container
kubectl get events --sort-by=.lastTimestamp
kubectl rollout status/undo deployment/api
kubectl scale deployment/api --replicas=5
kubectl port-forward svc/api 8080:80   # local access to a Service
kubectl top pod/node                    # live CPU/memory (needs metrics-server)
kubectl config use-context <ctx>       # switch cluster; -n sets namespace
kubectl apply -k ./overlays/prod        # Kustomize; --dry-run=client to preview

5. xUnit + Testcontainers

Spin up real Docker containers for integration tests instead of using mocks or in-memory DBs.

public class DbFixture : IAsyncLifetime {
    public PostgreSqlContainer Db = new PostgreSqlBuilder()
        .WithDatabase("testdb")
        .Build();

    public async Task InitializeAsync() 
        => await Db.StartAsync();

    public async Task DisposeAsync() 
        => await Db.DisposeAsync().AsTask();
}

Use [Collection("DbCollection")] to share the fixture across multiple xUnit test classes.

6. Nice to Have Skills

Redis

In-memory data store. Used for distributed caching (IDistributedCache), session state, and Pub/Sub messaging. Extremely fast key-value lookups.

Message Queue / Blob

  • MQ (RabbitMQ, Azure Service Bus): Decouples microservices. Enables async processing, event-driven architectures, and load leveling. (Tools: MassTransit, NServiceBus).
  • Blob Storage (AWS S3, Azure Blob): Storing unstructured data (images, PDFs) cheaply. DB only stores the URL/URI.

Helm

The package manager for Kubernetes. Packages YAML manifests into reusable Charts with templating.

helm install my-app ./my-chart
helm upgrade my-app ./my-chart

Helm Quick Commands

helm repo add bitnami https://charts.bitnami.com/bitnami; helm repo update
helm search repo/hub <keyword>              # find charts
helm install my-app ./chart -n prod --create-namespace \
     -f values.yaml --set image.tag=v2       # -f/--set override values
helm upgrade --install my-app ./chart --atomic --wait
                                             # idempotent; rollback on fail
helm template ./chart | kubectl apply -f -   # render locally (no Tiller since v3)
helm lint ./chart                            # validate chart
helm list -A                                 # releases across namespaces
helm history my-app; helm rollback my-app 1  # revision history / revert
helm uninstall my-app -n prod                # remove release
helm dependency update ./chart               # fetch subcharts (Chart.yaml)

OpenTelemetry

Vendor-neutral standard for Observability (Traces, Metrics, Logs).

builder.Services.AddOpenTelemetry()
    .WithTracing(tracer => tracer
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation()
        .AddOtlpExporter());

Auth0 / SAML Broker

Auth0: Identity as a Service (IDaaS).
SAML Broker: Acts as a middleman. Translates ancient enterprise SAML tokens into modern OIDC/JWT tokens so your app only needs to understand JWTs.
